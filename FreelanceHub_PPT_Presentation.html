MOTIVATION

2. Problem Statement (Challenges in Legacy Portals)

1. Exorbitant Fees

Legacy portals like Upwork and Fiverr charge up to 20% commission on earnings, discouraging young talent and SMEs.

2. Monolithic Lag

Legacy systems rely on multi-page server refreshes, causing slow navigation and poor mobile user experience.

3. Paid Bidding Barriers

Freelancers must buy paid 'Connects' just to submit proposals, creating an unfair barrier for emerging developers.

Speaker Note: "Existing platforms charge up to 20% commission and force freelancers to buy tokens just to apply. FreelanceHub eliminates these hurdles through an open, merit-based proposal workflow."
PROJECT GOALS

3. Key Project Objectives

  • Responsive Client UI: Build an intuitive user experience using React 19, Tailwind CSS, and Vite.
  • Stateless RESTful Backend: Implement high-throughput API endpoints in Node.js and Express.
  • Scalable Document Store: Design normalized schemas using MongoDB Atlas with Mongoose ODM.
  • Cryptographic Security: Secure sensitive routes via JSON Web Tokens (JWT) and BCrypt (10 salt rounds).
  • Contract State Machine: Deterministic lifecycle (Open → In-Progress → Completed → Mutual Reviews).
  • Turnkey Demo Seeder: One-command database population script for instant viva demonstration.
Speaker Note: "Our primary objective was building a production-grade, secure, and responsive full-stack platform following modern MVC and REST architectural standards."

SYSTEM DESIGN

6. System Architecture & Data Flow

+---------------------------------------------------------------------------------+ | TIER 1: PRESENTATION TIER (React 19) | | Navbar | Job Cards | Proposal Modals | Review Forms | Admin Panel | +----------------------------------------+----------------------------------------+ | HTTP REST Requests (JSON + Bearer Token) v +----------------------------------------+----------------------------------------+ | TIER 2: APPLICATION TIER (Express.js / Node.js) | | Controllers: Auth, Jobs, Proposals, Reviews, Admin, Users | | Middlewares: JWT protect, ErrorHandler, CORS, express.json() | +----------------------------------------+----------------------------------------+ | Mongoose ODM Wire Protocol v +----------------------------------------+----------------------------------------+ | TIER 3: DATA TIER (MongoDB Atlas Cloud) | | Collections: users, jobs, proposals, reviews | +---------------------------------------------------------------------------------+
Speaker Note: "The platform follows a clean 3-tier architecture: React in Tier 1 communicates via RESTful JSON APIs with Node/Express in Tier 2, which persists to MongoDB Atlas in Tier 3."
DATABASE MODELING

7. Database Design & Collections Schema

1. Users Collection

name, email, password (hash), role, bio, skills, hourlyRate, company, rating, totalReviews

2. Jobs Collection

client (Ref: User), title, description, category, skillsRequired, budgetMin, budgetMax, deadline, status

3. Proposals Collection

job (Ref: Job), freelancer (Ref: User), coverLetter, proposedBudget, deliveryDays, status ('pending'|'accepted'|'rejected')

4. Reviews Collection

job (Ref: Job), reviewer (Ref: User), reviewee (Ref: User), rating (1-5), comment, createdAt

Normalized relational integrity enforced using Mongoose ObjectId references and query-level populate().

Speaker Note: "Our database is normalized in 3NF across four collections: Users, Jobs, Proposals, and Reviews with strict relational ObjectId references."

WORKFLOW ENGINE

9. Contract Lifecycle & Bidding State Machine

[1. CLIENT POSTS JOB] ---------> Job Status = 'open' | v [2. FREELANCER SUBMITS BID] ---> Proposal Status = 'pending' | v [3. CLIENT ACCEPTS PROPOSAL] --> Proposal Status = 'accepted' Job Status = 'in-progress' All Other Proposals = 'rejected' | v [4. CLIENT MARKS COMPLETED] ---> Job Status = 'completed' | v [5. TWO-WAY 5-STAR REVIEWS] ---> Recalculate User Average Rating (1.0 - 5.0)
Speaker Note: "This state machine shows how contracts progress from 'open' to 'in-progress' upon proposal acceptance, and finally to 'completed' where mutual reviews are unlocked."
APPLICATION SECURITY

10. Security & Quality Implementation

Role-Based Access Control (RBAC)

  • Client Protected: Only clients can post jobs and accept bids.
  • Freelancer Protected: Only freelancers can submit bids.
  • Admin Protected: Strict role checks on /api/admin/* routes.

Encryption & Guardrails

  • BCrypt Hashing: Salt rounds = 10 prevent rainbow table lookups.
  • Stateless JWT: RFC 7519 tokens with 30-day expiration.
  • Duplicate Bid Guard: Database check stops repeat bidding on same job.
  • Projection Security: .select('-password') hides hash from APIs.
Speaker Note: "Security is reinforced with BCrypt password hashing, stateless JWT authorization, and strict server-side role validation."
